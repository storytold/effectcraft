# `.aep` / `.aepx` decoder — staged work checklist

> **Owner:** @PlayzAe · **Opened:** 2026-10-11 · **Tracking:** #251 (decoder + import), #190, #248, gap G4
> **Stage README:** [README.md](README.md) — update it at the end of every stage.
> **Format notes / provenance:** [format-notes.md](format-notes.md)

This is the long-form plan of record. It exists because the first two review passes on #251
(@echelon, @bflatastic) each landed on the same two root problems: **clean-room provenance** and
**tests that can actually fail in CI**. Both are addressed structurally here rather than patched.

Ordered as a gate chain. **Do not start stage *N+1* until stage *N*'s "Done when" is literally
true.** Every stage names a falsifiable exit condition so progress is measured, not self-graded
(craftrules `standards/progress-docs.md`).

---

## Ground rules (these outrank the schedule)

1. **Never crash.** `AGENTS.md` §"Never crash". This parser consumes untrusted binaries. Every
   offset, length and count that derives from input is read with `get(a..b)` and
   `checked_add` / `saturating_mul`. `usize` is **32-bit on wasm** — any `len as usize` from a
   `u32` field can wrap; use `usize::try_from(...)`.
2. **No non-test panics.** No `unwrap()` / `expect()` / `panic!` in `crates/engine`. The two in
   `viewer.rs` are review-flagged and must go.
3. **No `std::fs` in the engine crate.** Footage relinking goes through `Session.services` or the
   existing footage-check / relink flow (`crates/engine/src/footage_check.rs`).
4. **Clean-room.** See stage 0. Do not read third-party decoder *source* while implementing a
   format (`AGENTS.md` §2).
5. **Never commit Adobe-authored or third-party binaries.** Synthetic fixtures are generated by
   code in this repo; real-world samples belong in an external corpus repo
   (`storytold/photocraft-corpus` pattern, `AGENTS.md` §3).
6. **Bound everything.** Depth, node and item caps already exist (`MAX_CHUNK_DEPTH`,
   `MAX_CHUNK_NODES`, `MAX_PROJECT_ITEMS`); reaching **precomp references** needs its own seen-set,
   because comps can reference each other cyclically.

## S2 — Two-pass project table (the precomp fix)

**Why:** this is the reported bug — *"EffectCraft cannot tell when something is a precomp layer."*
It is architectural, not a one-line fix. Today `scan_item` fans items out into three unrelated
vectors (`comps`, `folders`, `footage`) and `build_project` reconstructs references from
`footage_ids` + `comp_by_raw_id` + two **name**-keyed maps. There is no single item namespace, so a
layer's `ldta` source id has nothing reliable to resolve against.

### Root cause, precisely
1. **No global item table.** Reference parsers keep one `Item` map keyed by the raw id, covering
   folders, comps, footage and solids in a **single namespace**. Ours does not.
2. **`is_text` / `is_shape` are tested *before* the comp lookup** (`aep.rs` ~1209–1210).
   `is_shape` is set by `mn.contains("ADBE Vector")` *anywhere* in the layer's `tdgp`, so a precomp
   containing vector content matches `Shape` first and never reaches `comp_by_raw_id`.
3. **`comp_ids` is keyed by name** (`aep.rs` ~1036), so duplicate comp names silently collapse; and
   `filter(|&&id| id != cid)` turns a self-referencing precomp into `LayerSource::Null`, which
   renders **nothing** — the empty viewer.
4. `footage_ids` is checked **before** the comp map, and both share the same raw-id space, so a solid
   / placeholder that shares a number with a comp wins.

### Tasks
- [ ] Introduce `RawProject { items: HashMap<u32, RawItem>, order: Vec<u32> }` and make **pass 1**
      walk the whole tree once, inserting **every** `Item` list: read `idta` type (`u16` @0) and id
      (`u32` @16), name, parent raw id, and the raw chunk children.
- [ ] **Pass 2** builds the `effectcraft_project::Project` from `RawProject`, allocating `ItemId`s
      for folders, then comps, then footage/solids, and keeping `raw_id -> ItemId` for **all** of
      them in one map.
- [ ] Resolve a layer's kind **only** from its resolved source item:
      `0x04` → `LayerSource::Comp`, `0x07` → `LayerSource::Footage` (or `Solid`), `0x01` → invalid
      on a layer, log and continue, **no** `Null` fallback.
- [ ] Delete the name-keyed fallbacks (`footage_by_name`, `comp_ids.get(&dlayer.name)`). Matching
      by name is what produces silent wrong-comp bindings.
- [ ] `LayerSource::Null` remains only for sources that are genuinely dangling; count them and put
      them in `AepReport` so the user sees "N layers could not be linked" instead of an empty frame.
- [ ] Cycle guard for precomp graphs: seen-set of raw ids, depth cap, on the **reference** walk.

**Done when:** `precomp_1` / `precomp_2_nested` import as `LayerSource::Comp` with the correct
target, `precomp_cycle` terminates, and a project with **two comps of the same name** resolves
each layer to the correct one (regression test for the name-keyed bug).

## S3 — Layer taxonomy

**Why:** layer kind is currently guessed from three sources at once: the container four-CC
(`Layr` / `SLay` / `CLay` / `SecL` / `AVLa` / anything `ends_with(b"Lay")`), the `tdgp` match-name
sniffing, and a `parent_folder == Some("Solids")` name comparison. That is three heuristics where
one fact exists.

### Tasks
- [ ] Define an explicit enum from the **container** four-CC only:

  | Four-CC | Layer |
  |---|---|
  | `Layr` | AV layer — resolve `ldta` source id to decide comp / footage / solid |
  | `SLay` | Solid layer |
  | `CLay` | Camera layer (skip `Custom View *` bookmarks) |
  | `LLay` | Light layer |
  | `SecL` | Marker / section layer |
  | other `*Lay` | unknown — record it in the report, do not guess a kind |

- [ ] `is_text` / `is_shape` become **content flags on a layer that is already known to be an AV
      layer**, never a kind selector. A text layer is `Layr` + `ADBE Text Properties`; a shape layer
      is `Layr` + `ADBE Vector Group`. Neither overrides the source binding.
- [ ] Solid detection stops using the folder name. It comes from the resolved source item's `opti`
      kind `0x09`. A solid referenced from a user folder is still a solid.
- [ ] Adjustment layers: `ldta` attribute bit at offset 38 bit 1. Wire it to the layer switch so
      adjustment layers import as adjustment layers.
- [ ] Parent/child links: the layer parenting id lives in the layer block; resolve it through the
      same raw-id table after all layers of the comp exist (third mini-pass within the comp).

**Done when:** a fixture for each layer kind asserts the exact enum value, and no code path decides a
layer's kind from a string match on `tdgp`.

## Appendix A — how to actually learn this format (the research loop)

The format was not designed to be read, and there is no spec. The only honest method is **controlled
differential observation of files you produce yourself**:

1. **Open one tiny project and read the whole tree.** Run a chunk dumper over it and print the nested
   four-CC tree with offsets, lengths and the first bytes of each payload. Do that on one project
   before writing any parser code, so the shape of the container is in your head.
2. **Change exactly one thing.** Add a solid. Add a precomp. Convert a layer to a precomp. Rename an
   item. Parent one layer to another. Change a comp's fps. Save, dump again, diff the two dumps. The
   changed byte range *is* the field.
3. **Repeat until a field's meaning is pinned by two independent diffs.** One diff is a coincidence.
4. **Encode the finding as a fixture assertion immediately** (S1). A finding that is not in a fixture
   will be lost and silently regressed.
5. **Only then look at a published structural map** to check you are not idiosyncratic to one file.
   Reading someone's *source* while implementing is out of bounds under `AGENTS.md` §2.

Videos and blog posts about "how `.aep` works" are useful for the **model** — the object graph
(project → folders → items → comps → layers → properties) — and useless for offsets. Offsets come
from the diff loop. The model comes from Adobe's scripting documentation, which is the
specification-tier source in [format-notes.md](format-notes.md) §1.

## Appendix B — what is inside an opened project (the model to reproduce)

This is the object graph the decoder has to reconstruct:

```
Project
├─ expression engine, bits-per-channel depth
├─ Fold "root"
│  ├─ Item (type 0x01 Folder)
│  │  └─ Item (type 0x01 Folder)          nested via Sfdr
│  ├─ Item (type 0x04 Composition)        -> cdta: w, h, fps, duration, bg
│  │  └─ Layr ...                         -> ldta: source id, in/out, attribute bits
│  │     ├─ tdgp                          -> transform, effects, text, vector content
│  │     └─ source id ----+
│  ├─ Item (type 0x07 Footage)           -> alas: path; Pin /sspc: w, h, duration
│  └─ Item (type 0x07 Footage, solid)    -> opti kind 0x09
└─ a layer's ldta source id resolves into the item tree above
```

The important consequence: **a precomp layer is not a special kind of layer.** It is an ordinary
`Layr` whose `ldta` source id happens to point at an `Item` of type `0x04`. Anything in the decoder
that tries to recognise a precomp by looking at the layer itself is wrong by construction — which is
exactly defect #1 in [README.md](README.md).
